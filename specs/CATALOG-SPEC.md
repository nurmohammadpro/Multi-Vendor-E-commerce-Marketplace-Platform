# Catalog Spec

## Scope

- categories
- brands
- products
- product variant definitions
- product variant values
- SKU variant combinations
- SKUs
- price history
- media

## Core Tables

- `catalog.categories`
- `catalog.brands`
- `catalog.products`
- `catalog.product_media`
- `catalog.product_variant_groups`
- `catalog.product_variant_options`
- `catalog.skus`
- `catalog.prices`

## Rules

- products are never hard-deleted
- valid product states: `active`, `inactive`, `archived`, `out_of_stock`
- price changes create new rows in `catalog.prices`
- store-scoped uniqueness on `product_code` and `sku_code`
- variants are manual, not auto-generated by category
- each product may define its own variant groups such as `color`, `size`, `front_rear`, `weight`, `material`
- each variant group may have many manual options such as `red`, `xl`, `front`, `5kg`
- a SKU represents exactly one sellable combination of selected variant options
- variant order must be preserved for UI and barcode label readability
- duplicate SKU combinations for the same product are blocked
- stores may use single-variant products, simple products, or multi-variant matrix products
- product-level variant definitions are flexible enough for clothing, tires, hardware, electronics, and custom stores
- SKU search must support barcode-first lookup for POS
- product detail responses should include variants, SKU pricing, and stock summary
- categories and brands are tenant-level reference data reused across stores under the same platform tenant
